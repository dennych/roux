# 桥式（Roux）分步还原 · Web MVP

一个**保证能真的还原**的桥式教学网页：给出打乱 → 按阶段显示"下一步（公式名称）" → 点击后屏幕魔方同步演示这一步的变化，并在每一步后用引擎校验你做到哪了。

## 怎么用

1. 直接用浏览器打开 `index.html`（纯静态，双击即可，不需要服务器、不需要联网、没有任何依赖）。
   - **立体视图**：26 个小方块拼装的 CSS 3D 魔方，有缝隙、遮挡和随视角变化的逐面光照；按住拖动可 360° 旋转，默认缓慢自动旋转（可取消勾选）。
   - **平面展开图**：一键切换成十字展开图，六个面同时可见，适合对照自己的实体魔方核对。若浏览器/预览器不支持 CSS 3D（`preserve-3d` 被压平，立体视图会塌成一个面），页面会自动切到这个模式。
   - 点「下一步」时，魔方会**真的把这一层转给你看**（不是直接跳变），转动过程中会显示"正在转：X (2/4)"。
   - **「每步转动」滑块**：控制每一转的时长，0.2–3.0 秒可调，**默认 1.5 秒**（慢速便于对照手上的魔方）；设置会记住。
     转动时长里约 70% 用于转层动画、30% 用于停留，所以每一转都看得清。
   - 「自动播放本阶段」再点一次即可**停止播放**（停止时画面与逻辑状态始终一致）。
   - **「拆步」下拉框**：控制每一步最多几转，默认 **≤3 转**。公式会被拆成子段，必须**人工点一次「下一步」才走下一段**
     （例：`小鱼（Sune）` 7 转会变成 `第 1/3 段 R U R'` → `第 2/3 段 U R U2` → `第 3/3 段 R'`）。
     可选 ≤1 / ≤2 / ≤3 / ≤4 / ≤6 转或「整条公式」；**总转数完全不变**，只是分组更细；
     改这个设置时会**按已完成的转数保留进度**。
   - **180° 转（`U2`/`M2`/`R2`…）在转动序列里用高亮标出**，并且动画后停留时间加长 60%，不容易漏。
   - **「暂停 ⏸ / 继续 ▶」**：执行过程中随时可以暂停（会停在这一转结束处，画面同时冻结，方便对照手上的魔方）；
     暂停时「上一步」会变成「**放弃本步**」，点它可回滚到本步开头重做。快捷键 **P** 也能暂停/继续。
2. 页面上会给出一串打乱，把它做在你的实体魔方上（**朝向随意，但整局固定一种配色**）。
3. 选阶段（左桥 / 右桥 / CMLL / LSE），点 **下一步 →**，屏幕魔方会把这一步的每个转动依次演示出来，同时显示公式名和转动序列。
4. 右侧"状态校验"面板是"你做对了没有"的判定：左桥 1×2×3、右桥 1×2×3、顶层角块、坏棱数量、整体还原。
5. 也可以点"完整计划"里的任意一步直接跳转；键盘 ← / → 也能上一步/下一步。
6. 想复现某一局：地址栏加 `#scr=R+U+F%27+L2+D+B+R%27`（自定义打乱），或加 `&cursor=6` 直接跳到第 6 步之后。

## 朝向约定（默认：黄顶 · 红前 → 左桥蓝 / 右桥绿）

**默认朝向**：`U` = 黄（顶）、`D` = 白（底）、`F` = 红（前）、`B` = 橙（后）、`R` = **绿**（右桥）、`L` = **蓝**（左桥）。
也就是"左右两条桥分别是蓝面和绿面"的那种摆法（黄顶、白底、红前）。

页面上的「朝向」下拉框可一键切换（三种都是标准配色的合法持法）：

| 选项 | U / D | F / B | R / L | 左桥 / 右桥 |
|---|---|---|---|---|
| **黄顶 · 红前**（默认） | 黄 / 白 | 红 / 橙 | **绿 / 蓝** | **蓝 / 绿** |
| 黄顶 · 橙前 | 黄 / 白 | 橙 / 红 | 蓝 / 绿 | 绿 / 蓝 |
| 黄顶 · 绿前 | 黄 / 白 | 绿 / 蓝 | 橙 / 红 | 红 / 橙 |

切换的是**面→颜色的标签**，几何与记法（`U/F/R` 仍是上/前/右）不变，
所以「下一步」里的 `U/R/M` 永远指你手上对应的那一层，跟着转不会错位。
跟着走之前，请把实体魔方摆成与下拉框里一致的朝向（默认：**黄顶 · 红前 · 右面绿**）。

## 约定的公式（只有 3 条）

| 公式 | 转动 | 用途 |
|---|---|---|
| 小鱼（Sune） | `R U R' U R U2 R'` | CMLL 阶段 1：调整顶层角块**朝向** |
| 反小鱼（Antisune） | `R U2 R' U' R U' R'` | 同上 |
| T-perm | `R U R' U' R' F R2 U' R' U' R U R' F'` | CMLL 阶段 2：调整顶层角块**位置** |
| （辅助）AUF | `U` / `U2` / `U'` | 顶层对位，配合上面三条使用 |

这三条公式 + AUF 经程序验证可以覆盖**全部 648 种**顶层角块情况（先朝向、后换位；朝向阶段最长 4 条、换位阶段最长 3 条）。
所有公式的"合法性"都由引擎验证：施加后左右两桥必须完好、角块必须还原。

## 步骤是怎么来的

| 阶段 | 求解方式 | 实测（本次实现） |
|---|---|---|
| 左桥 FB | IDA* + 两个模式数据库（角 504 / 棱 10560 状态），搜索全部 12 个面转 | 平均 **7.0 步**（理论最优平均 7.13，最长 9） |
| 右桥 SB | IDA* + 两个模式数据库，转动集限制为 ⟨U,R,M,r⟩（**天然不破坏左桥**） | 平均 **10.1 步**（子问题最优平均 9.96，最长 14） |
| CMLL | 在 648 个角块状态图上 BFS，只用上面 3 条公式 + AUF（两阶段；并与"一步搜索"比较取更短者） | 平均 **4.4 条公式**，步数偏长是"少公式"的代价 |
| LSE | 预计算 M/U 全表（92160 状态）→ 沿最短距离贪心下降 = **最优解**；再用里程碑标注 4a/4b/4c | 平均 **11.2 步**（理论最优平均 10.85，最长 20） |

整条链路平均约 **56 步**（含公式转动；桥式实战平均约 48 STM，差距主要来自"只用 3 条 CMLL 公式"）。

每一步生成后引擎都会断言阶段不变量（左桥还原 / 两桥完好 / 角块还原 / 整体还原），不满足就直接报错——**不会出现"跟着走却还原不了"的情况**。

## 可视化是怎么做的（为什么有立体感）

| 做法 | 效果 |
|---|---|
| **26 个小方块（cubie）拼装**，每个方块 6 个面各一个贴纸格 | 方块之间留 2px 真实缝隙，近处方块遮挡远处方块，不再是一张平面贴图 |
| 每格贴纸按**方向**着色，没有贴纸的方向显示黑色塑料 | 转动时能看清"哪个块转走了" |
| **逐面光照**：按当前视角算出 6 个方向的亮度（上亮、前中、右暗…），拖动时实时变化 | 立体感的主要来源；拖动时只更新 6 个 CSS 变量，不重排 DOM，保持流畅 |
| **真实转层动画**：把该层 9 个方块临时放进一个组里旋转，动画结束后按引擎的置换表落位 | 点击「下一步」真的能看到 M/U/R 层在转 |
| **目标块高亮**：左桥/右桥阶段给目标位的方块加蓝框 | 一眼看出这一步该把哪些块放哪里 |
| 地面阴影 + 透视 + 深度渐变背景 | 增强悬浮感 |

## 输入你自己的魔方（拍照读色 → 状态串）

**这是给"手上已经有一个随意打乱的魔方"用的**，不需要你照着随机打乱去复现。

1. **拍 3 张照片**（前两张顶层色朝上，第三张翻过来）：
   - **A**：45° 俯视 → **上 / 前 / 右**
   - **B**：绕竖直轴转 180°（顶层色仍朝上）→ **上 / 后 / 左**
   - **C**：上下翻转（原来的**前面保持朝前**）→ **下 / 前 / 左**
   > 为什么是 3 张：任何 45° 视角都只能看到"三对相对面里各一个"，同一顶色的两张最多覆盖 5 个面，
   > 第 6 面要靠约束推断；拍 3 张就 6 面全覆盖，还能互相校验。
   要求：**不要用手指遮挡**（放桌上，或只捏边缘）、光线均匀（避免贴纸反光/白面过曝）、
   魔方占画面 1/3 以上、对焦清楚、背景干净。
2. 把照片发到对话里，并告诉我**顶面中心 / 正面中心是什么颜色**。
3. 我逐格读色后给你一串 **54 个字母**（例如 `YYYYYYYYYBBBBBBBBBRRRRRRRRRGGGGGGGGGOOOOOOOOOWWWWWWWWW`）。
4. 粘到页面「**输入我的魔方**」→「解析并载入」，页面会做三重校验：
   颜色计数（每色 9 格）、每个角/棱是否是真实块、以及角块扭角 / 棱块翻转 / 角棱奇偶三个不变量。
   通过后按你给的颜色渲染出来，**先和实物核对**，再点「下一步」逐步执行。
   也可以直接用链接：`index.html#state=<54 个字母>`。

**状态串格式**：顺序 `上 U / 左 L / 前 F / 右 R / 后 B / 下 D`，每个面 9 格「从左到右、从上到下」；
字母表示颜色：`W` 白 `Y` 黄 `G` 绿 `B` 蓝 `R` 红 `O` 橙（空格换行会被忽略）。

**任意持法**：页面「朝向」下拉框可以设成"任意顶面色 + 任意前面色"（24 种持法）；
导入的状态会按你给的颜色显示，记法里的 `U/F/R` 永远指你照片里的上/前/右那一层。

### 照片怎么给我（三条入口，任选）

| 入口 | 怎么做 | 说明 |
|---|---|---|
| **① 直接在对话里贴图**（最快） | 把两张照片拖进对话，顺便说一句顶/前中心色 | 零设置 |
| **② 放进 `photos/` 目录** | 存成 `photos/photo-1.jpg`、`photos/photo-2.jpg`，然后跟我说"照片放好了" | 目录说明见 `photos/README.md`，我可以直接读这个目录 |
| **③ 网页里当场拍** | 打开 `index.html` →「拍照 / 选图」→ 打开摄像头 → 拍两张 → 点「写入 photos/ 目录」 | 直接写目录需要 Chrome/Edge（File System Access API）；Safari 会改成下载，再手动移进 `photos/` |

### 摄像头能不能用（MacBook Pro）

- 每台 MacBook Pro 都有内置摄像头，浏览器可用 `getUserMedia` 调用，首次会弹权限。
- 用 `file://` 打开时：Chrome 把 `file://` 视为安全上下文，通常可用；**Safari 经常不行**。
  稳妥做法是在项目目录起个本地服务：`python3 -m http.server 8777`，然后开 `http://127.0.0.1:8777/index.html`。
- 有 iPhone 的话，macOS 的「连续互通相机」可能让 iPhone 出现在摄像头列表里（角度更灵活），是否被 Chrome 列出需要试。
- 内置摄像头是"从屏幕方向看"，拍桌面上的魔方要摆好笔记本角度；所以**更推荐手机拍照 → 传 `photos/` 或直接贴对话**。
- 「写入 photos/ 目录」依赖 File System Access API（Chrome/Edge 支持），不支持时自动改为下载文件。

## 动画转向的正确性（v5 修了一个真 bug）

**问题**：`F` / `B` 两个转动的**动画方向反了**（U/D/R/L/M/r 都是对的）。

原因：方块在屏幕上按 `CSS 坐标 = S·模型坐标`（`S = diag(1,-1,1)`，因为 CSS 的 y 轴朝下）摆放，
所以动画的旋转矩阵必须等于 `S · 模型矩阵 · S`，即 **角度取反、轴取 S·n**。
`F` 的模型旋转是"绕 +z 转 -90°"，对应 CSS 应为 `rotateZ(+90deg)`，而代码写成了 `rotateZ(-90deg)`；
`B` 同理写反。后果：动画把 F 层**逆时针**转给你看，落地时色块却按**顺时针**的结果归位
（"执行后和执行中不一样"）；若你照着动画在实物上转，实物就会和屏幕分道扬镳。

**把关**：`node test_cssrotation.js`（24 个转动全覆盖，两个判据）

1. **矩阵一致**：动画会用到的 CSS 矩阵 == `S · 模型矩阵 · S`（模型矩阵用引擎 `rotateCoord` 在层内点上交叉验证）；
2. **视觉等价**：把"动画转到 90° 时屏幕上会出现的 位置+朝向+颜色 集合"与"落地后按新状态重上色的集合"逐格比对，必须完全相同
   （这正是"执行中 ≡ 执行后"的形式化）。

该测试对 bug 版会失败（20/24），对修复版全过（24/24）；浏览器里 `rotateX/Y/Z(90deg)` 的实际矩阵也已核对与推导一致。

## 画面自检（排障用）

「状态校验」卡片里有一个 **「画面自检（画面 vs 引擎）」** 按钮：它会逐格比对**屏幕上的 54 个色块**与**引擎里的状态**，
并检查有没有残留的旋转组。结果直接显示在按钮旁边：

- `✓ 画面与引擎一致（54 格）` → 显示没问题
- `✗ 有 N 格不一致：<位置>| <方向>: 画面X 期望Y` → 渲染出问题的**具体格子**，方便直接报给我

配套的渲染健壮性（v4）：

- 转层动画的收尾（方块归位 + 重新上色 + 移除旋转组）放在 `finally` 里，**异常/被打断也一定会执行**；
- 每次整体重绘前会**清理任何残留的旋转组**（自愈），所以不会出现"某一层停在半路、颜色一直不对"；
- 被中断的旧动画**不会再按旧状态上色**（用令牌判定），避免"旧动画把旧颜色写回屏幕"。

## 手动填色（不依赖照片，最可靠）

页面「**手动填色**」卡片：选颜色（白/黄/绿/蓝/红/橙/橡皮）→ 在十字展开图上点格子 → 填满 54 格 →
点「校验并开始还原」。同样会做三重校验，通过后**从头重算**方案、光标回到第 0 步、屏幕魔方切到新状态，
并把状态串自动填进上面的输入框（「下一步」按钮会闪一下 + 弹出总步数）。

- **「重设（清空并重新开始）」**：一键清空填色、状态串、方案与「下一步」面板（回到"未开始"），
  方便换一颗魔方重新填；同时会清掉地址栏里的 `#state=`/`#paint=` 参数，避免刷新后又把旧状态载回来。
- 校验**失败也必然可见**：红字说明 + 弹窗提示 + 自动滚动到错误处（不会再出现"点了没反应"）。
- 每次载入还会做**自检**：如果画面和刚载入的目标状态不一致，会直接报红字（提示点「重设」重来）。
- 想从已还原状态开始改，可先点「填入还原态」。
- 页面右上角有**构建标记**（当前 `v3（重设 · 载入自检 · 可见面提示）`）。如果看不到它，
  说明浏览器用的是缓存的旧脚本 —— 按 **Cmd+Shift+R** 强制刷新。

## 已知限制（下一版可以补）

1. **CMLL 用 3 条公式换来"少公式"，步数偏多**（平均 4.4 条公式）。补 42 条 CMLL 一步到位公式表后，CMLL 可压到约 10 步。
2. **打乱是随机转动序列**，不是 WCA 随机状态打乱；接入 `cubing.js` 可换成正规随机状态打乱，并顺带获得更漂亮的动画与智能魔方支持。
3. **LSE 的 4a/4b/4c 只是里程碑标注**：最优解可能穿插进行，所以有时会退化成"LSE · 第 k 段"。若想要严格分段的 4a→4b→4c，平均要 20 步（引擎已验证），教学上不划算。
